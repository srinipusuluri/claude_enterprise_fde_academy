Tech Stack Tools

A layer-by-layer reference catalog for building, deploying, securing and operating enterprise AI systems with Claude. Treat this as a selection map—not a requirement to use every tool.

FDE principle: Select the smallest reliable stack that satisfies the customer’s security, data-residency, latency, scale, integration and operating-model requirements. Standardize interfaces and telemetry so individual tools can be replaced.

05 / PRODUCTION OPTIMIZATION PLAYBOOK

Optimization: Claude cost, security, observability & performance

Move beyond a working prototype. Optimize the full system around cost per successful task, response quality, latency, reliability, security and operational visibility.

Optimization objective: Minimize total cost and time per successful business outcome while preserving quality, security and reliability. Do not optimize token cost in isolation if it increases retries, failures, human rework or risk.
01 • Cost economics

Understand Claude unit economics

  • Token accounting: measure input tokens, output tokens, cached input tokens, cache writes, batch usage and model-specific rates.
  • Cost per task: calculate inference + retrieval + tools + infrastructure + observability + human review / escalation.
  • Cost per successful outcome: total operating cost divided by successfully completed, quality-accepted business tasks.
  • Model economics: compare Opus, Sonnet and Haiku by task complexity, success rate, latency and cost—not price per token alone.
  • Context economics: long system prompts, duplicated history, retrieved passages and tool schemas can increase input spend on every request.
  • Agent economics: track model calls per task, tool calls, retries, handoffs, planning loops, failed actions and total tokens across the complete trace.
  • Budget controls: per-user / tenant / workflow budgets, token ceilings, output limits, concurrency caps, quotas and alerts.
  • Chargeback: attribute usage by customer, team, environment, feature, model and workflow.

Use the official Claude pricing documentation for current model and feature rates. Recalculate when pricing or model versions change.

02 • Cost reduction techniques

Reduce waste without degrading quality

  • Prompt caching: place stable system instructions, policies, examples and tool definitions in cacheable prefixes; keep dynamic user content later in the prompt.
  • Prompt compression: remove duplicated instructions, unused examples, verbose tool descriptions and irrelevant conversation history.
  • Context engineering: retrieve only relevant passages, use metadata filters, deduplicate chunks and cap context by task.
  • Model routing: route simple classification / extraction to a smaller model and reserve stronger reasoning models for complex, high-value tasks.
  • Output control: request concise structured output, set appropriate max output tokens and avoid generating content the application can calculate deterministically.
  • Batch API: move eligible offline workloads—classification, enrichment, evaluations and backfills—to batch processing where latency requirements permit.
  • Reuse: cache deterministic application results, embeddings, retrieval results and approved intermediate outputs with clear freshness and tenant boundaries.
  • Agent budgets: set maximum turns, tool calls, wall-clock time and retry count; stop when success criteria are met.
  • Parallelism: parallelize independent retrieval or tool calls, but avoid redundant fan-out and uncontrolled concurrent model requests.

Measure quality before and after each optimization. Prompt caching and batch eligibility, limits and economics are feature- and model-dependent.

03 • Latency & throughput

Improve end-to-end performance

  • Time-to-first-token (TTFT): use streaming for interactive experiences and render partial output safely.
  • Latency decomposition: measure queue time, application time, retrieval, model time, tool execution, network overhead and post-processing separately.
  • Right-size context: reduce unnecessary history, large tool schemas, oversized retrieved documents and repeated instructions.
  • Tool efficiency: consolidate overly granular tools, use narrow schemas, parallelize independent calls and avoid serial round trips where safe.
  • Connection management: reuse HTTP connections, apply sensible timeouts, use async I/O and avoid blocking application workers.
  • Concurrency: use bounded queues, backpressure, rate-limit-aware scheduling, exponential backoff with jitter and tenant-level fairness.
  • Resilience: handle 429 / 5xx responses, transient network failures, timeouts, partial streams and downstream tool outages.
  • Model selection: choose the smallest model that meets the measured task-quality threshold; route up only when needed.
  • Load testing: test realistic prompt sizes, concurrency, burst patterns, tool delays and multi-tenant workloads.

Track p50 / p95 / p99 latency, throughput, timeout rate, retry rate and successful tasks per minute—not just average response time.

04 • RAG & data-path optimization

Make retrieval faster and more relevant

  • Retrieval quality: tune chunk size, overlap, top-k, metadata filters, hybrid search weights and reranker thresholds against a golden dataset.
  • Index strategy: use appropriate vector dimensions, distance metrics, partitions, namespaces and indexes for workload scale.
  • Freshness: incremental ingestion, change detection, scheduled refresh, deletion propagation and stale-content monitoring.
  • Permission filtering: enforce user / group / record ACLs before content reaches the model; do not rely on prompt instructions to hide unauthorized data.
  • Context packing: deduplicate, diversify and order retrieved passages; preserve source IDs and citation metadata.
  • Query transformation: rewrite ambiguous queries, expand acronyms and decompose multi-part questions only when evaluation proves value.
  • Fallbacks: detect no-answer / low-confidence cases and ask a clarifying question, search another source or route to a human.
  • Evaluation: measure retrieval recall, precision, MRR / nDCG, groundedness, citation accuracy, freshness and permission leakage.

Tune retrieval and generation separately. A fluent answer does not prove that the retriever found the right evidence.

05 • Security optimization

Reduce risk while preserving usability

  • Least privilege: grant each agent, MCP server and tool only the minimum required scopes and actions.
  • Identity propagation: bind user identity and tenant context to downstream calls; avoid shared credentials that bypass user-level authorization.
  • Prompt-injection defense: treat retrieved documents, emails, web pages and tool outputs as untrusted data; isolate instructions from data.
  • Tool controls: allowlist tools, validate arguments server-side, restrict destinations, enforce schemas and require confirmation for high-impact actions.
  • Data minimization: send only necessary fields to the model; redact secrets and sensitive data from logs, traces and evaluation datasets.
  • Network controls: private connectivity where supported, egress restrictions, DNS / URL allowlists and SSRF protections.
  • Output handling: validate structured output, encode content before rendering and treat model output as untrusted input.
  • Abuse controls: user / tenant quotas, anomaly detection, rate limits, content safeguards and incident kill switches.
  • Security testing: run prompt-injection, data-exfiltration, cross-tenant, tool-abuse and authorization regression tests before release.

The model is not an authorization boundary. Enforce policy in application code, identity providers, MCP servers and downstream systems.

06 • Observability & traceability

Instrument the complete agent lifecycle

  • Distributed traces: propagate trace / span IDs across frontend, backend, Claude calls, retrieval, MCP, tools and downstream services.
  • Core dimensions: tenant, user pseudonym, workflow, session, model ID, prompt version, tool name, MCP server, retrieval source IDs and environment.
  • Cost telemetry: input / output / cached tokens, cache reads and writes, model calls, batch usage and estimated cost.
  • Quality telemetry: task success, refusal, groundedness, citations, tool success, escalation, user correction and evaluator scores.
  • Performance telemetry: TTFT, total latency, per-tool duration, queue delay, retries, timeouts and throughput.
  • Security telemetry: denied actions, policy decisions, approval events, anomalous tool calls, authentication failures and data-access events.
  • Business traceability: correlate request ID with CRM case / opportunity / account, source document, approval and resulting transaction ID.
  • Dashboards & alerts: service SLOs, model availability, cost spikes, latency regressions, failure rates, quality drift and suspicious behavior.
  • Privacy-aware telemetry: redact payloads, restrict trace access, define retention, sample appropriately and separate production data from test fixtures.

A useful trace answers: who asked, what context was retrieved, which model ran, what tools were called, what changed, who approved it, how long it took and what it cost.

07 • Reliability & graceful degradation

Keep the workflow safe when dependencies fail

  • Define SLOs for availability, latency, task completion, tool success and data freshness.
  • Use circuit breakers, bounded retries, idempotency keys and dead-letter queues for downstream actions.
  • Provide deterministic fallback paths for unavailable models, tools, retrieval services or cloud dependencies.
  • Use human review for high-impact actions and low-confidence or policy-sensitive outcomes.
  • Separate read-only tools from write-capable tools; make writes explicit, auditable and reversible where possible.
  • Run canary deployments and shadow evaluations before rolling out prompt, model, tool or retrieval changes.
  • Maintain incident runbooks, rollback procedures, support ownership and post-incident learning.

Optimization workflow

Run a disciplined improvement loop

1. Establish baseline

Capture representative task quality, tokens, cost, latency, failure rate and security findings.

2. Find the bottleneck

Use traces and evaluations to isolate prompt, model, retrieval, tool, network or infrastructure costs.

3. Form one hypothesis

Example: “A smaller model can handle this classification task with no material quality loss.”

4. Test offline

Run a versioned golden dataset, adversarial cases, regression checks and cost / latency comparisons.

5. Canary rollout

Release to a limited cohort with guardrails, dashboards, rollback and human review.

6. Validate business impact

Compare cost per successful task, cycle time, user acceptance, risk and operational load.

Claude Enterprise

Best starting point for employee-facing assistants, internal knowledge discovery, document analysis and team productivity workflows using approved enterprise context and controls.

Claude Code

Best fit for software engineering workflows: repository understanding, implementation assistance, tests, code review and developer productivity. Keep code changes reviewable and CI-validated.

Build custom customer-facing or embedded agents with your application identity, business logic, retrieval, tool execution, UI, evaluation and telemetry.

Build or operate longer-running tool-using agent workflows with controlled tools, state, execution boundaries and application-level monitoring. Validate current availability and deployment fit.

MCP and connectors

Expose enterprise systems and approved actions through governed integrations. Enforce authorization in each server and downstream application; MCP itself is not an access-control policy.

Claude Cowork and Skills

Support repeatable knowledge-work tasks with reusable instructions and workflows. Use only approved connectors, scoped access and human review for sensitive outputs or actions.

Build one agent end to end

Example: Product KB Search Agent implementation

1. Sources

Connect product docs, release notes, support articles and approved repository markdown; capture owner, version, ACL and updated timestamp.

2. Knowledge pipeline

Parse, chunk, embed and index content; support incremental refresh, deletion propagation, metadata filters and permission-aware retrieval.

3. Claude experience

Use Claude Enterprise for employee discovery or the Claude API for an embedded portal; instruct Claude to cite retrieved evidence and say when evidence is missing.

4. Tools & MCP

Expose search, product-version lookup and feedback submission as narrow tools; keep search read-only and validate all tool arguments server-side.

5. Security & evaluation

Test access boundaries, prompt injection, outdated answers, citation accuracy and no-answer behavior using a versioned golden question set.

6. Operate & improve

Trace queries, retrieval IDs, model usage, latency, cost and user feedback; monitor freshness and improve based on failed searches.

QualityTask success, groundedness, citation accuracy, escalation rate

EconomicsCost per successful task, tokens, tool and human-review cost
AdoptionActive users, repeat usage, workflow completion, user feedback
RiskPolicy violations, data exposure, override and incident counts
Threat model: what can go wrong?
  • Indirect prompt injection hidden in retrieved documents or web content.
  • Over-permissioned MCP tools exposing or modifying sensitive records.
  • Cross-tenant retrieval leakage caused by missing authorization filters.
  • Secrets or PII captured in prompts, logs, traces or error messages.
  • Unbounded agent loops, runaway spend or repeated external actions.
  • Model/provider changes that silently regress critical workflows.

Mitigate with defense in depth: authorization outside the model, narrow tools, output validation, egress controls, budget limits, eval gates, audit and rollback.

11 / INTERVIEW PREPARATION

Practice the FDE interview

Be ready to reason through ambiguous customer scenarios, not just recite tools.

Discovery scenario

A bank wants Claude to reduce contact-center handling time. What do you ask before proposing an architecture?

Architecture scenario

Design a Claude agent that reads Salesforce cases and approved knowledge, drafts a response and requests approval before sending.

Debugging scenario

After launch, answer quality drops and p95 latency doubles. How do you isolate retrieval, model, tool and infrastructure causes?

Security scenario

A retrieved document contains instructions to export confidential customer records. How does your system defend against this?

Deployment scenario

The customer requires private networking, centralized identity and audit integration. What must be validated with the selected deployment provider?

Value scenario

The demo is popular but users still complete the workflow manually. What metrics and product changes would you investigate?

Discover deeply. Build pragmatically. Deploy responsibly. Prove value.
